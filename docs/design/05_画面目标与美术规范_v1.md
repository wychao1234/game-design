# 画面目标与美术规范 v1

日期：2026-10-16  
状态：整体美术方向与选定战斗图的人物大小、镜头距离已获用户确认；具体实现参数仍为提案。开发暂停；本稿未制作角色动作、3D场景或可用游戏资产。附录提示词对应AI生成的目标样稿，不是游戏截图。镜头、像素密度、服装细节和资产规模须经未来样板验证。

## 1. 要达到的实际体验

采用精致像素角色与有纵深的立体东方场景。参考《八方旅人》所呈现的微缩舞台层次、局部灯光与材质气氛，同时围绕本作的实时走位、聚怪、连击和换人重新设计镜头与空间。建筑、人物、怪物和器物均按自己的东方志怪世界制作。

画面首先让玩家看见自己的位置、敌人的动作和能走的路，再用雨、水、灯火、瓦墙与远景表现冒险气氛。场景应当像能走进去的古镇和秘境；战斗区须有足够空间让剑、枪、投射物和召唤形成不同打法。美术不能只在静态空场成立。

选关、难度、掉落目标、结算和成长使用清楚的界面循环；装饰来自纸、铜、织物与封禁纹样，不照搬已有游戏的图标或面板。

## 2. 两张目标样稿与用途

| 样稿 | 设定与构图 | 重点验证 |
| --- | --- | --- |
| A：临川镇雨夜 | 暖灯商铺、青瓦白墙、石桥与河埠；主角位于画面中下部，商人和少量行人提供尺度，出口通向右侧渡口 | 是否愿意停留；路线、交互与建筑层次能否同时看清 |
| B：雨灯渡口战斗 | 宽木码头作为主要战场；近战敌人、远程敌人和持钩精英分层；主角斩击、地面预警、单只灯灵和一件掉落同时出现 | 混战可读性、角色比例、特效边界、掉落与HUD是否冲突 |

“日常雨夜”指可正常逛店与整备的夜间生活场景，不是昼夜两套画面的承诺。设计目标是相容的斜角视角、角色比例与调色；实际首轮成图的镜头展示倍率有差异，详见第11节。不做一张宣传海报、一张俯视游戏图。

战斗样稿设为祝听澜入队后的旧关回访。雨灯渡口首次进入时，她尚未入队；回访状态允许展示三头像编队和已施放灯灵。画面上只有沈砚一位人类战斗角色，江照野、祝听澜仅出现在HUD；灯灵属于持续效果。镇上可出现伙伴NPC，不能由此推导战斗时三人同屏。

2026-10-16用户确认选定战斗图的整体方向满意，并保持当前人物大小、动作辨识与镜头距离。服装、建筑和界面在该方向内细化；生成图中的文字、动作细节、透视和碰撞空间仍不能直接充当制作规格。图像生成完成后，应根据实际图面另记通过点和偏差。

## 3. 镜头、比例与像素密度

建议固定斜角镜头，近似正交或弱透视；俯角先以45°～55°范围试验。镜头不随鼠标旋转，不在普通连招中突然拉近或改变地面朝向。玩家朝向、技能指向、地面落点保持同一套空间关系。

以1920×1080显示为讨论基准，截图样稿可为1536×864。早期曾提议48～64个源像素、显示80～110像素及屏高8%～10%，这些只是未验证的起点。用户现已选择保持战斗样稿中较大的人物显示比例；恢复制作时以该选定图的可见人物与战场关系为基准，再实测换算相机和贴图参数，不用早期估值把人物缩小。源像素、方向数和帧数仍未定案。角色贴图采用清晰像素采样；角色、怪物与可拾取物使用相容密度。场景材质不必刻意把所有木纹都像素化，但细节颗粒不能压过角色。

实战中至少能同时看清近战范围、一次闪避的去向和主要远程威胁。首领镜头可温和拉远，不能缩到只剩人物光点。镜头跟随有小幅前视，边缘遇到墙体保持稳定；角色在屏幕中下方可给前方更多观察空间。参数全部需要键鼠移动与战斗样板验证。

## 4. 色彩与灯光层次

| 层级 | 色彩提案 | 作用 |
| --- | --- | --- |
| 环境基底 | 深靛蓝、灰青、湿石灰，如#172B3B、#365B60、#8B9690 | 统一雨夜材质，避免大面积纯黑吞掉细节 |
| 生活灯火 | 低饱和琥珀与纸白，如#D99645、#E7D6AF | 引导商店、桥头、入口和安全停留区 |
| 玩家招式 | 象牙白刀光、少量青色边缘 | 交代攻击轨迹，不能覆盖脚下预警 |
| 敌方危险 | 暖红橙加明确边线、纹理及方向提示 | 同时依靠形状、时序和颜色辨识危险 |
| 特殊掉落 | 细光柱、地面小标记、品质形状 | 不用整屏闪光抢占战斗注意力 |

亮度次序是当前威胁与角色动作最高，交互和重要掉落其次，生活灯火与背景细节再次。不同品质掉落保留不同图标或边框形状，颜色不是唯一信息。友方阵地使用细冷色边界，敌方预警使用明确暖色边界与填充规律；实际还需检查灰阶和色觉差异可读性。

灯光从环境底光、局部灯火、角色技能和气氛层四层建立。湿地反射压低亮度、降低边缘锐度，不复制出一片同亮度假角色。雾和雨分近远层，战斗地面只留轻薄空气感。泛光以不吞掉像素轮廓为上限，灵术可以发亮但仍保留形状。

## 5. 四人的小尺寸识别

角色姓名仍采用阵容稿暂名；祝听澜的女主身份、灵动可靠性格与符铃召唤已确认。以下服装和配色属于新美术提案。

| 角色 | 轮廓、姿态与主色 | 小尺寸必须保留的特征 |
| --- | --- | --- |
| 沈砚 | 炭蓝短衣、浅腰带、赭红缠臂；轻微前倾，单手契刀 | 左臂标记、刀的弧线、短衣形成轻快轮廓 |
| 江照野 | 较宽肩背、旧灰铁护甲、土黄布料；持长枪压低重心 | 长兵器占据横向空间，站姿稳，不能像放大的主角 |
| 祝听澜 | 米白与浅青层叠衣装、短披帛、少量朱符；侧身举铃 | 铃的手势、可控的披帛轮廓、灯灵点状光；避免细饰堆叠 |
| 陆惊弦 | 紧袖、短下摆、深紫灰配铜色器件；机巧短弓与背侧箭匣 | 弓和箭匣形成不对称轮廓，瞄准姿态与施符明显不同 |

先用黑色剪影确认四人，再做三阶明暗与有限配色，最后加饰件。立绘可以展示复杂衣纹，战斗像素图优先保留三到五个辨识点。装备成长先做可见武器、阶段装束和觉醒变化，不默认六槽每件装备都实时改变全部方向的身体像素。

妖灵借形采用短暂、不完整的异形轮廓，不能表现为常驻第五位人类队友。乌岐外形还未定，本轮只规定攻击形状与主角动作有关系，不自行锁定兽种或完整人形。

## 6. 敌人、特效与掉落的视觉优先级

普通近战、远程施术与精英分别用身形、器械与准备动作区分。雨灯渡口可先试纸傀类轻敌、投掷敌与持钩精英；这属于敌人美术提案，不等于新增剧情种族。纸傀衣形不能与主角、女主的披帛混淆。精英的武器轮廓和蓄力动作应在特效出现前可识别。

普通攻击使用短促、薄而有方向的轨迹；重击增加停顿、接触火花与敌人受击反馈；觉醒保留局部高潮，不长时间白屏。屏幕震动、拖影和泛光均应可调。光效不替代动作准备、命中声音和受击姿态。

地面预警优先于友方装饰；施法者、弹体和危险落点可以对应。掉落光柱细窄且低于预警亮度，远离角色脚下的关键区域。战斗中标签合并、短显或按键展开；战斗结束再提供完整比较。普通物资不各自生成强光，稀有获得的庆祝在安全时突出。

## 7. HUD布局提案

| 区域 | 内容 | 约束 |
| --- | --- | --- |
| 左上 | 三人头像、各自生命与倒地状态、当前角色高亮、切换提示 | 头像不是三个在场单位；第四位候补不挤入进图HUD |
| 右上 | 小地图、短任务目标、可选掉落目标进度 | 不用长任务段落占据战场 |
| 下中 | Q／E／R／F四个普通技能、X独立觉醒格、一条共享能量、两枚闪避资源提示 | 槽位及冷却清楚，装饰留在边缘；切换规则以系统稿为准 |
| 上中 | 首领生命与破势信息，仅需要时出现 | 不与小地图、目标文字重叠 |
| 近目标 | 交互提示、克制的异常状态和掉落名称 | 避免持续堆叠伤害数字 |

城镇界面收起大型战斗信息，保留整备与交互捷径。背包、关卡地图与结算使用同一字号和图标体系。1080p下主要文字先试20～24像素，再检查缩放；HUD不采用必须放大观看的微小像素字体。生成样稿可用图标和少量占位短标识，正式文字需后续真实界面排版。Q／E／R／F与X只是本轮统一的键位提案，实际需要可改键；交互键不与技能E共用，最终对应关系由战斗与工程稿统一。

## 8. 遮挡、景深与地面可读性

建筑高处、前景桥柱和船棚不得长期遮挡玩家与敌人。可采用淡出屋檐、可移除前景层、受遮挡角色轮廓提示；以不露出错误碰撞关系为前提。木箱、绳索和台阶的装饰形状，应能判断是否阻挡、能否破坏或跨越。

景深仅用于远景、极近前景和非战斗演出。活动战区、落点与敌人准备动作保持清楚，不通过大面积虚化制造“精致”。雨线、草叶、符纸等小运动限制密度；不让危险边缘与场景纹理形成高频混杂。桥头、码头和水面边缘的可走范围须一致，不靠模糊黑边暗示隐形墙。

## 9. 按动作和方向拆分资产预算

数量须经一个角色与一组敌人样板验证，不能把生成一张角色图当作完成角色资产。先比较四向与八向：四向省量但斜向移动易显僵硬，八向轮廓准确但动作量明显增加；镜像方向也需要检查持械、缠臂和不对称衣饰。

| 资产组 | 需要拆分的项目 | 预算方法 |
| --- | --- | --- |
| 可培养角色 | 待机、移动、普攻连段、闪避、受击、倒地、进出场、四个首批技能 | 每动作×所需方向×帧数，武器与身体是否分层另计 |
| 后续技能与觉醒 | 各候选技能的动作、投射物、落点、命中、残留效果 | 不能把36个技能条目当作36张图标；允许有意复用动作但保留差异 |
| 召唤与借灵 | 灯灵、灵犬、阵地、短妖影；出现、持续、攻击、退出 | 独立单位与一次性特效分别核算，遵守系统并发上限 |
| 敌人与首领 | 移动、准备、攻击、受击、破势、死亡；首领各招式 | 先做完整招式可读性，再增加换色或外观变体 |
| 场景 | 地面、岸线、墙屋、桥船、交互、破坏物、遮挡层、灯与水 | 以可复用模块加手工地标组成，不承诺五地区同一套换色 |
| 界面与音效 | 技能和装备图标、头像、地图、提示；挥击命中与预警音 | 规格统一，音画共同验收 |

首批样板需覆盖一位完整近战角色、一位主动召唤角色、一组远近敌人与一只具明确招式的精英，再检查四人轮换的轮廓兼容。此处为美术验证顺序，不改变完整版四人和五地区目标，也不代表恢复开发。

动作预算还要区分准备、有效攻击与恢复阶段：斩击有几帧不重要，玩家能否提前看懂方向、是否准确感到接触更重要。方向素材可以有意复用躯干，但武器轨迹、手部和脚底接触必须同步，不能用水平镜像让左臂标记来回跳动。首个样板完成后，记录每个动作的绘制、调试和返修工时，再估算整队及五地区；没有样板数据前，不承诺固定素材总张数或制作周期。

## 10. 评审标准与交接

第一轮由美术提出本稿，交由战斗策划与工程、测试核查镜头、HUD和并发效果。第二轮结合实际生成图修订，纠正后的结论见第11节。两张图在正常显示尺寸检查：第一眼认出主角；看见敌人准备姿态；判断预警和可走地面；辨别一件掉落；不用放大才能找到四技能与觉醒。附录描述设计意图；实际生成提示词会为HUD键位等作小幅细化，成图仍须逐项核对，不依据提示词宣称已经满足。

后续恢复开发时还需在动态画面验证移动稳定、像素边缘、粒子叠加、遮挡切换、文字缩放与实际帧率。静态样稿仅帮助选择方向，不证明能达到性能或素材制作成本。不得将AI目标图标成实机、量产素材或已经完成的关卡。

若样稿第一眼主要吸引人的是巨大人物立绘、满屏光柱或不可行走的精美建筑，应重新调整构图。交接时保存镜头角度、角色尺寸、灯光层级和HUD占位的对照表；后续场景可以更华丽，但要持续服从同一套战斗识别标准。

## 11. 实际生成图评审记录

2026-10-16，美术已实际查看两张首轮生成图、B第一次纠正图及B最终资源HUD纠正图，而非只按提示词评审。当前交付采用A城镇图与B最终纠正图，可供用户判断气氛、空间和战斗信息布局方向；正式UI、动作与实机尺度仍待制作验证。两张图都是AI目标样稿，不是已制作场景或游戏运行截图。

| 项目 | 临川镇雨夜A | 雨灯渡口战斗B首轮 |
| --- | --- | --- |
| 空间和氛围 | 石桥、河埠、店铺和远景形成连贯层次；雨水与灯火有生活感，主角所在桥面可辨认 | 码头中央留出较宽战场，水面和船只在边缘提供地域感；主角、四个普通敌人与一个精英能分开辨认 |
| 战斗信息 | 城镇交互图标与底部捷径较克制；未展示实际交互或路径碰撞 | 斩击方向、单只灯灵、地面长条预警和独立掉落位置可见，没有额外人类队友同场 |
| 镜头比例 | 广角环境构图，人物较小，用于讨论城镇气氛 | 明显放大战斗人物和动作，用于展示识别关系；与A不是相同展示倍率 |
| HUD偏差 | 左上存在无名蓝条，易被理解为额外MP，正式UI需删除或明确已有资源含义 | 首轮各头像下蓝条容易被当作MP；闪避显示两亮一暗共三个菱形，与总上限2不符；英语任务、掉落货币袋与本轮中文装备展示目标不一致 |
| 仍待证明 | 建筑淡出、行人避让、真实出口路径及地图对应关系 | 普通敌人近战剪影相似，尚未明确展示远程单位准备动作；仅凭静图不能验收远近混编、攻击判定和闪避落点 |

首轮B需要纠正HUD后再次查看：保留环境、单人在场、单灯灵及敌人数量；闪避总数改为2，去除无名蓝色资源条，任务和装备标签用中文，并明确共享觉醒资源。头像属于构图占位，不能据此锁定伙伴白发、衣饰等正式人设。A的无名蓝条列入正式UI修订，不因此否定城镇气氛方向。
