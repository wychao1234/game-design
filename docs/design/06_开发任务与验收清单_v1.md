# 开发任务与验收清单 v1

日期：2026-10-16  
状态：工程蓝图，供恢复开发前评审。本轮只完成设计拆分，没有检查游戏源代码、运行新测试或制作新关卡；表中交付物与证据均为后续要求。

## 1. 制作目标与边界

沿用此前Godot路线，面向Windows键鼠游玩；具体引擎版本、渲染后端、插件可用性和导出链需恢复工程后核验。目标电脑配置、分辨率与性能档位尚未取得，不承诺FPS、内存上限或交付日期。

架构覆盖五地区、四角色、四选三、单角色在场与城镇选关刷宝。首批D2只制作临川镇、雨灯渡口和独立舟主关，不制作R1-01、R1-03～06，不能宣称从全新档连续通第一章。渡口用遵守正史的隔离预置进度档验证双人闭环，三人画面取祝入队后的回访状态；后期／隔离测试档验证三套轮换与舟主。解锁条件夹具不等于关卡已做。E阶段补齐第一章，才从全新档验证渡口、后续主线、R1-06、R1-B及祝招募的连续流程。

此前简陋样板提供了战斗、掉落和保存方面的探索经验，但不能据此认定新方案已经完成。恢复工作时先盘点可复用内容，再决定改造；禁止未经核对重写整个项目，也不把占位地图按钮当作五地区完成。

## 3. 场景与数据清单

首批需要启动与存档选择、临川镇、整备与背包、地区选关、加载与恢复提示、雨灯渡口、可发布的独立R1-B舟主关、结算、暂停与设置。舟主关必须有完整碰撞、招式预警、阶段推进和独立结算，不能只有测试场或首领敌人条目。背包可作覆盖层；另保留与正式旅程隔离的训练场和测试入口。

数据先登记R1～R5及40入口的结构、状态与解锁引用；未制作条目标注未制作，不能进入空白地图。将“入口”“任务阶段”“难度”分开，允许同一目录承载真正不同的任务内容，禁止用不同血量副本充当新增内容量。

| 数据对象 | 标识与必须记录的信息 |
| --- | --- |
| 角色、技能、装备模板 | 固定ID；显示名称与资源路径可改变，存档不靠名称引用 |
| 实际装备 | 唯一实例ID、模板ID、等级档、属性、锁定状态、装备者 |
| 任务与选择 | 任务ID、阶段、首次线索、选择值及已触发事件 |
| 一趟地下城 | 唯一运行ID、入口、任务、难度、编队、奖励记录 |
| 一次效果 | 施放ID、源角色、源技能、来源类别、剩余寿命、触发上限 |
| 一次奖励 | 唯一事务ID、获得原因、资源变化、物品实例、提交状态 |

ID只是设计约定，具体命名格式交由实现统一。存档不持久化场景节点引用、动画播放位置或已经卸载的陷阱对象。

## 4. 资源归属与结算契约

战斗效果保留原施放角色归属；切人不改伤害来源、不重置冷却、标记、召唤寿命或共享资源。基础伤害参数按施放时取值、目标防御按命中时取值；临时加成在效果配置中指明计算位置，避免重复计入。同技能重放和各类效果上限依照03稿执行；来源倒地清除其持续效果，房间卸载清除场地与陷阱，跨房间对象只保留明确允许的类别和剩余寿命。

觉醒能量同趟跨房间保留，结算、退出、失败重试清空。自动召唤、后台区域和派生攻击不产能；手动驱令按一次施放上限计入。伤害、产能、装备触发分别记录来源类别。机制装备须按04稿逐件定义来源白名单、施放ID和单次触发上限，装备派生攻击禁止再次触发装备机制。验证同时命中多目标、多段命中和持续按键时，同一施放不超限，非白名单来源触发为零，派生链下一层为零。

永久获得与临时战斗状态分开处理：装备、经验、材料和永久解锁在确认获得后形成奖励事务并保存；正常失败不回滚这些成长，敌人、临时效果和当前战斗资源重新开始。拾取显示与存档提交保持一致，无法保存时明确提示并保留可重试记录，不静默显示“已获得”。

首通奖励以任务首通标记限制，重复奖励以每趟运行ID区分。重进结算、切场景或读档不能重复执行同一事务；新的合法重刷可正常获奖。兑换、升级、拆解必须同时保存扣除与所得。采用完整写入后替换及可恢复备份；写入中断、文件损坏、旧版迁移要能失败退出或恢复，不能直接覆盖唯一存档。遇到未知旧物品ID先保留原数据和备份，避免当作垃圾批量删除。

## 7. 三个扩展门槛

**视觉门槛。** 实际游玩分辨率下能辨角色、敌人、武器、地面危险和掉落；建筑可遮挡但不能隐藏正在攻击的敌人，景深与雨雾不模糊战斗区域。概念图只能确认方向，不能证明像素采样、动作或可玩，也不直接作为代码绑定资产；须以真实引擎镜头、动图和玩家观察验证。密集特效、灯光、水面及召唤同时出现时，在目标Windows机器记录CPU、GPU、内存与帧时间，再设画质档位。没有实机不能宣布性能达标。

**手感门槛。** 键鼠移动、瞄准和技能方向一致，近战不会因斜角视觉频繁挥空；反馈对应真实命中。四角各有主动操作理由，换人衔接收益可解释，首领可识别并应对，失败原因能从画面理解。记录首次体验与熟练操作问题，再调取消窗口、距离和节奏，不以理论数值证明好玩。

**系统门槛。** 从城镇出发、掉落成长、回城保存、重开再刷连续成立；反复切换不刷新资源，源效果不串装备，结算不重复，正常重刷仍有收益。通关不依赖毕业套装。任一门槛未通过，暂停批量铺地区与技能素材，先修代表流程；数据目录和后续策划可以继续。

## 8. 必须留下的验证记录

测试清单至少覆盖：键鼠改键与UI输入冲突；连续换人、同帧受击与倒地换人；自主召唤、阵地、延迟攻击及陷阱的独立上限和归属；换房间与读档的能量及寿命；结算双击、返回、重复加载和合法重刷；兑换或拆解中断；批量拆解排除装备、锁定及特殊保护物；背包满时收益去向；全队死亡保留已获得成长；不同入队节点、后台追赶与剧情登场；损坏存档及版本恢复。

四条觉醒检查分别以沈、江、祝、陆为当前角色，使用共享100能量初值触发，确认只有当前角色执行且扣除一次；再覆盖取消、换人、同帧重复输入，不得双扣、双放或误用新角色觉醒。制作阶段测试可解锁，正式档仍遵守剧情条件。每项证据含构建标识、前置存档、步骤、预期与实际结果，数值附账本、画面附录像；正式与测试存档分别回归。

首次通关30小时以上包含自愿培养，但目前仍是制作目标。后续分别统计新内容、可选探索、返刷、失败和等待；40入口目录、概念图与系统框架都不能证明时长。用户尚未提供目标Windows配置，性能标准与资源方向数等待实际验证；所有阶段当前均未宣称完成。
